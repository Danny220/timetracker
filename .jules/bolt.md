## 2024-05-05 - Missing Memoization in Critical Render Path
**Learning:** In React components (like `WeeklyTimesheet.tsx`) rendering arrays of items with complex computed sub-states (e.g. checking if a day is a holiday dynamically for every single cell during re-renders), repeated invocations of date formatters and complex logic like `getEasterSunday` cause huge CPU overhead.
**Action:** When evaluating dates repetitively, implement simple module-level dictionary caching for year-based static data (like holidays) and avoid repeated `format()` calls by reusing already formatted `yyyy-MM-dd` date strings to dramatically reduce latency.
## 2026-05-10 - Do Not Memoize isToday
**Learning:** In React components (like `WeeklyTimesheet.tsx`) rendering arrays of items with complex computed sub-states (e.g. checking if a day is a holiday dynamically for every single cell during re-renders), repeated invocations of date formatters and complex logic like `getEasterSunday` cause huge CPU overhead. However, do NOT memoize time-dependent calculations like `isToday` using `new Date()` that rely solely on static dependencies (like `weekStartDate`). Doing so causes stale state regressions when the application is left open across day boundaries (past midnight).
**Action:** Pre-compute expensive repetitive properties (like date formatting from `date-fns` and complex calculations like `isNonWorkingDay`) once per prop-change using `useMemo` into an array of static descriptor objects. Calculate time-dependent values like `isToday` directly within the render loop to ensure they evaluate dynamically and avoid stale data.
