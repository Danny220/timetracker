## 2024-06-10 - Project Assignment Authorization Bypass
**Vulnerability:** Employees were able to log time entries (via the API) for activities associated with projects they had not been assigned to. The database RLS policy for `time_entries` INSERT only verified that `user_id` matched `auth.uid()`, without checking `project_assignments`.
**Learning:** Over-relying on frontend filtering (the UI only fetched assigned projects) without backend verification leads to Insecure Direct Object References / Authorization Bypasses when attackers directly interact with the API. RLS policies or database triggers must comprehensively validate all authorization rules.
**Prevention:** Always enforce business rules at the database level. For complex hierarchical authorization checks (like checking an assignment on a parent project when inserting a child activity record), either integrate `EXISTS` queries into the RLS policy or enforce them securely in database triggers (as done in `public.enforce_time_entry_status()`).
